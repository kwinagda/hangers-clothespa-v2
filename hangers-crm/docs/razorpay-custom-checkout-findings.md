# Custom Checkout Build Findings

## Acceptance Findings - 1 October 2026

- F65 (new, report-only observability/correlation gap; 2 October 2026): source review finds useful but fragmented records: selected public checkout actions write ActivityLog/AuditLog; signed Razorpay events have a durable inbox and worker outcome; notification dispatch has outbox/activity stages. This is not one end-to-end structured trace across browser milestones, API requests, attempts, provider callbacks/status checks, webhooks, ledger allocations and outbox delivery. `RazorpayCheckoutAttempt.id` is unique per attempt; `requestId` is per HTTP request; neither is a durable parent across several confirmed-unpaid attempts. Ad-hoc `console.error` paths also remain, and browser telemetry cannot establish payment truth. A22 now proposes three deliberately distinct identifiers: Hangers `paymentJourneyId` as the durable business correlation parent for one collection journey and its safe retries; unique `checkoutAttemptId` for each provider-order attempt; and W3C Trace Context trace/span IDs for individual synchronous distributed operations, with each async webhook/worker operation separately traced and linked back to the journey. Razorpay order/payment/event IDs are linked only when they exist and are confirmed against server records. This follows the separation between merchant references and provider references in payment lifecycle documentation and between business context and request traces in distributed tracing standards. Acceptance still requires defining durable journey creation/linkage and retry/terminal semantics, testing redaction and log-write failure visibility, access/retention controls and fault-injected lifecycle traces. “Every event” means meaningful state transitions, not keystrokes or field values. PAN, CVV, both OTP classes, full contact details, tokens/secrets, raw provider payloads and unapproved error text remain excluded. No logging implementation, schema or production configuration has been changed for this finding. References: https://docs.adyen.com/account/payments-lifecycle/ ; https://www.w3.org/TR/trace-context/ ; https://opentelemetry.io/docs/specs/otel/logs/.
